## 2025-02-18 - State Synchronization and Accessible Interaction inside Multi-View Feed Feeds
**Learning:** In interactive social feeds built with Next.js/React, split visual representations of the same underlying data (e.g., standard feed cards versus full-screen story overlays) require lifting interactive state (like/share interactions) to a shared parent layout (`FeedView.tsx`). Additionally, when using the Web Clipboard API (`navigator.clipboard`) to provide delightful copy-to-clipboard utility, we must check if `typeof navigator !== 'undefined'` to prevent Next.js build-time server-side execution crashes, and immediately follow up with an animated temporal notification tooltip ("Copied!") so the action is perceptible to both visual and keyboard/screen-reader users.
**Action:** When designing feature interactions across multiple viewport modes (grid, detail, story overlay), lift interactive state up immediately, apply accessible, high-visibility keyboard rings (`focus-visible:ring-2 focus-visible:ring-offset-2 focus-visible:ring-blue-500 focus-visible:outline-none`) combined with accurate `aria-pressed`/`aria-label` labels, and safely handle browser-only features behind SSR environment guards.
