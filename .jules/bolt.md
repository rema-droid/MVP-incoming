## 2026-08-10 - O(1) Single-Pass Jargon Replacement & Summary Caching
**Learning:** Sequential string replacements in utility functions like `simplifyWords` not only suffer from O(N * M) CPU overhead due to dozens of individual regex iterations, but also introduce double-expansion/double-replacement bugs (such as matching and replacing a word that was already inserted as part of a previous translation). Pre-compiling a sorted key mapping list into a single, unified case-insensitive RegExp solves the double-expansion correctness issue completely and runs over 4x faster. Furthermore, using a FIFO-evicted cache Map for calculations that depend on relatively static API objects (like GitHub repository details) avoids redundant string work altogether, achieving massive O(1) performance improvements in hot paths.
**Action:** Always replace chained/sequential regex replacements with a unified single-pass RegExp replacer mapped to a dictionary, and introduce FIFO Map-based result caching for heavy natural language calculations.
