## 2025-05-24 - Hoisting Jargon Replacements and Caching Repository Summaries
**Learning:** Re-declaring and re-allocating a large array of jargon replacement patterns (76 items) and compiling raw RegExp patterns on every call within standard list rendering functions like `summarizeRepoForBeginners` creates significant garbage collection overhead and CPU cycles, particularly during keystroke search inputs or high-frequency polling. Hoisting these elements statically to the module level and implementing an O(1) Map cache with size-limited FIFO eviction results in over 23x faster performance.
**Action:** Always statically hoist regular expression patterns and lookups outside of render/utility loops, and implement bounded, safe FIFO/LRU memoization caches for pure functions processing rich metadata objects with stable identifiers (like `repo.id`).
