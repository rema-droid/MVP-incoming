## 2025-05-10 - [Command Injection and Argument Injection in Build Pipeline]
**Vulnerability:** The build engine was using `child_process.exec` with unsanitized user input (GitHub URLs and Repo IDs) to run shell commands like `flyctl` and `git clone`. Additionally, `git clone` was vulnerable to argument injection where a malicious URL starting with `-` could be interpreted as a command flag.
**Learning:** Shell-based process execution (`exec`) is inherently risky when dealing with external inputs. Even with "safer" alternatives like `spawn`, utilities like `git` can still be tricked by malicious arguments if they aren't explicitly separated from options.
**Prevention:** 1. Always use `spawn` with `shell: false` and pass arguments as an array. 2. Sanitize all inputs used for OS-level resource names (directories, app IDs). 3. Use the `--` separator for CLI tools that support it to explicitly mark the end of options. 4. Validate external URLs against a restrictive allowlist regex.
