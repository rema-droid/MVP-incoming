## 2026-04-01 - Command Injection via Shell Execution in Background Worker
**Vulnerability:** The background queue worker cloned repositories and deployed apps to Fly.io using `child_process.exec` (via a promisified `exec` wrapper) with unsanitized `githubUrl` and `repoId` parameters, exposing the system to Command Injection / Remote Code Execution (RCE).
**Learning:** Under the hood, `exec` spawns a shell to run command strings, which interprets shell metacharacters (like `;`, `&`, `|`, `` ` ``, `$()`). Even simple input validation checks can fail to protect shell-based APIs if they are too loose or bypassable.
**Prevention:** Always avoid shell-spawning functions like `exec` or `spawn` with `shell: true` when passing user-controlled parameters. Instead, use non-shell execution functions like `execFile` or `spawn` with an array of arguments and `shell: false` so parameters are treated strictly as arguments rather than executable shell code. Additionally, enforce multi-layer input validation (at both REST API and background worker boundaries) using strict regular expressions.
