## 2025-07-31 - Command Injection Prevention via Input Validation
**Vulnerability:** Command injection and path traversal via unvalidated user repository URLs (`repo.url`) and repository IDs (`repo.id`). These values were passed directly into shell commands like `git clone` and `flyctl` via `child_process.exec`.
**Learning:** Background workers and local runtimes that execute shell scripts using untrusted payloads must validate inputs at both the REST entry point and the worker/processing layer (Defense in Depth). Even when the input passes initial API-level checks, matching them against strict regular expressions prevents command-chaining or directory traversal markers from reaching shell executors.
**Prevention:** Strictly validate repository URLs against a restrictive regex like `GITHUB_URL_REGEX = /^https:\/\/github\.com\/[a-zA-Z0-9-._]+\/[a-zA-Z0-9-._]+(\.git)?$/` and sanitize any identifier interpolated into file paths or app names with a regex like `/^[a-z0-9-]+$/`.
