## 2026-04-01 - Command Injection in Background Deployment Worker
**Vulnerability:** The background worker was executing unvalidated and unsanitized parameters (`githubUrl` and `repoId` / `appName`) received via the `Run Cloud` queue directly in shell-executing commands like `git clone` and `flyctl apps create` via Node's `child_process.exec`. An attacker could submit a payload containing shell meta-characters (such as `;`, `&`, `|`, `` ` ``), leading to remote code execution (RCE) on the host machine.
**Learning:** Shell-executing child processes like `exec` (which run commands inside `/bin/sh -c`) represent a significant command injection risk. This risk is amplified if user inputs bypass validation at the REST/API layer, or if background queue workers assume the incoming payload was already validated.
**Prevention:** Always validate all queue parameters and API inputs using strict regular expressions (such as `GITHUB_URL_REGEX` and `APP_NAME_REGEX`) that only permit safe characters, and enforce this validation at both the entry API router and the consumption/worker level (defense-in-depth). Where possible, prioritize non-shell execution or strictly parameterized argument arrays (e.g. `spawn` with `shell: false`).
