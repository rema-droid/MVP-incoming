## 2025-07-30 - Shell Command Injection in Build-Engine Background Worker
**Vulnerability:** The build-engine background worker `build-engine/worker.ts` executed raw shell commands (`flyctl apps create`, `git clone`, `flyctl deploy`) via `execAsync` (which wraps `child_process.exec`) using completely unsanitized, user-provided repository URLs (`githubUrl`) and repository/app IDs (`repoId`). A malicious user could supply a crafted repository URL containing shell metacharacters (e.g. `; rm -rf ...`) to execute arbitrary shell commands inside the worker runtime environment.
**Learning:** Background queue workers are often treated as "internal" and assumed to receive sanitized inputs from the REST API layer, leading to missing validation checks in asynchronous tasks. However, defense-in-depth requires checking input validation at both the REST gateway and the worker consumer layer to prevent any payload from bypassing initial checks or being corrupted inside the queue.
**Prevention:** Always sanitize or validate inputs using strict allowlists (e.g., `GITHUB_URL_REGEX` and `APP_NAME_REGEX`) before interpolating them into shell commands, and prioritize non-shell execution environments (like `child_process.spawn` or `safeExec`) wherever possible.
