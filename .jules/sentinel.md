## 2025-08-05 - Untrusted Runtime Request/Response Proxy Vulnerability
**Vulnerability:** Proxying HTTP requests and responses to/from untrusted sandbox runtimes without sanitizing headers allows session hijacking, token leakage, and cookie tossing. Specifically, standard authentication headers like `Cookie` and `Authorization` were passed to third-party code running in the sandboxes, and untrusted responses were permitted to set arbitrary host/session cookies via `Set-Cookie`.
**Learning:** Proxying endpoints must explicitly sanitize both input and output headers using an allowlist or a strict blocklist when dealing with untrusted upstream hosts. Deleting `host` and `content-length` is insufficient when session context can be transferred.
**Prevention:** Enforce a centralized, secure proxy utility (`proxyRequest`) that strips sensitive request credentials (`cookie`, `authorization`, `proxy-authorization`) and deletes response headers that alter the host's session context (`set-cookie`).
