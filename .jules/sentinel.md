## 2026-04-01 - Background Worker Command Injection & Incomplete Temp Cleanup DoS
**Vulnerability:** Direct interpolation of unsanitized repository URL (`githubUrl`) and repository ID (`repoId`) from Redis/BullMQ job data into shell execution commands (`git clone`) and CLI commands (`flyctl apps create`). This allowed remote command injection. Additionally, temporary workspace directory cleanup was performed using shell commands (`rm -rf`) outside a `try...finally` block, creating a potential disk-space exhaustion Denial-of-Service (DoS) if a deployment failed.
**Learning:** In asynchronous architectures combining web controllers with background workers, enforcing validation solely at the API controller boundary is insufficient. Malicious queue injections or direct Redis state manipulation could bypass REST input validation and execute arbitrary code on backend runners. Furthermore, relying on shell-dependent helpers for cleanup in execution paths prone to failure can lead to severe system resource exhaustion.
**Prevention:**
1. Always validate inputs at both the REST API ingestion layer and the worker processor boundary (defense-in-depth).
2. Avoid shell invocation for cleanups; always use native Node.js methods (e.g., `fs.rm` with `{ recursive: true, force: true }`) wrapped within structured `try...finally` blocks to guarantee secure teardown of untrusted artifacts.
